# 接口约定文档

本文档用于统一三种二叉搜索树实现（非平衡 BST、AVL 树、Splay 树）的接口规范，保证各成员的模块可以无缝对接评测程序。**主要数据结构与算法统一使用 C 语言实现。**

## 1. 目录与文件结构

```
project-1/
├── docs/                  # 文档
├── include/
│   └── tree_ops.h         # 统一接口声明（函数指针表）
├── src/
│   ├── bst/
│   │   ├── bst.h          # 非平衡 BST
│   │   └── bst.c
│   ├── avl/
│   │   ├── avl.h          # AVL 树
│   │   └── avl.c
│   └── splay/
│       ├── splay.h        # Splay 树
│       └── splay.c
├── bench/
│   └── bench.c            # 评测程序
└── Makefile
```

## 2. 编译与环境约定

- 语言标准：C99，编译命令统一为 `gcc -std=c99 -O2 -Wall -Wextra`
- 不依赖任何第三方库，只使用标准库（`stdio.h`、`stdlib.h`、`string.h` 等）
- 每个实现编译为独立的目标文件，由 Makefile 链接，禁止在实现之间共享内部结构体定义

## 3. 键类型约定

- 统一键类型为 32 位整数：

```c
typedef int tree_key_t;
```

- 树中不允许出现重复键（键集合语义），如需扩展再另行约定
- 节点结构体、树的内部表示由各实现自行定义，**不对外暴露**，对外只以 `void *` 句柄传递

## 4. 统一接口

每个实现对外提供同名前缀的五个函数，签名完全一致（以 AVL 为例，`bst`、`splay` 同理替换前缀）：

```c
void *avl_create(void);
int   avl_insert(void *tree, tree_key_t key);
int   avl_erase (void *tree, tree_key_t key);
int   avl_find  (void *tree, tree_key_t key);
void  avl_destroy(void *tree);
```

### 4.1 函数语义

| 函数 | 语义 | 返回值 |
| ---- | ---- | ------ |
| `create` | 创建并返回一棵空树；失败返回 `NULL` | 树句柄 |
| `insert` | 插入键 `key` | `0` 成功；`1` 键已存在（不做修改）；`-1` 内存分配失败 |
| `erase`  | 删除键 `key` | `0` 成功；`1` 键不存在 |
| `find`   | 查询键 `key` 是否存在 | `1` 存在；`0` 不存在 |
| `destroy`| 释放树中全部节点及树本身，之后句柄不可再用 | 无 |

### 4.2 参数约定

- 传入 `NULL` 句柄时，除 `create` 外一律返回 `-1`（`find` 返回 `-1` 表示错误），评测程序保证不会这样调用
- 所有函数不得修改全局状态，不需要考虑线程安全

## 5. 函数指针表（供评测程序使用）

评测程序通过统一的操作表驱动三种实现，各实现在头文件中额外导出一个常量表：

```c
typedef struct {
    const char *name;                                  /* "bst" / "avl" / "splay" */
    void *(*create)(void);
    int   (*insert)(void *tree, tree_key_t key);
    int   (*erase) (void *tree, tree_key_t key);
    int   (*find)  (void *tree, tree_key_t key);
    void  (*destroy)(void *tree);
} tree_ops_t;

extern const tree_ops_t avl_ops;   /* bst.c 中导出 bst_ops，splay.c 中导出 splay_ops */
```

`include/tree_ops.h` 中只包含 `tree_key_t` 与 `tree_ops_t` 的定义，各实现的头文件 `#include` 它，避免重复声明。

## 6. 复杂度与行为要求

| 实现 | 插入 | 删除 | 查询 | 备注 |
| ---- | ---- | ---- | ---- | ---- |
| 非平衡 BST | 期望 O(log n)，最坏 O(n) | 同左 | 同左 | 不做平衡 |
| AVL 树 | 最坏 O(log n) | 最坏 O(log n) | 最坏 O(log n) | 需维护平衡因子/高度并旋转 |
| Splay 树 | 均摊 O(log n) | 均摊 O(log n) | 均摊 O(log n) | 查询命中后需将节点伸展至根 |

- 三种实现对相同输入序列的可见行为必须一致（即 `find` 的结果与键集合语义一致）
- `insert` 对已存在的键不产生任何副作用；`erase` 对不存在的键不产生任何副作用

## 7. 内存管理约定

- 节点分配使用 `malloc`，失败时 `insert` 返回 `-1`，不允许直接终止进程
- `destroy` 必须释放全部节点，不允许内存泄漏

## 8. 代码风格约定

- 命名：类型 `snake_case_t`，函数 `<前缀>_<动作>`（如 `avl_rotate_left`），宏全大写
- 每个模块的头文件加 include guard（`#ifndef BST_H` 形式）
- 各成员只修改自己目录下的源文件与头文件；如需改动公共文件（`tree_ops.h`、Makefile、评测程序），须在小组群中说明

## 9. 联调与验收流程

1. 各成员完成实现后，在本地跑通评测程序的冒烟测试
2. 提交 PR 至仓库，由负责评测程序的成员在评测程序上统一跑正确性与性能测试
3. 接口如有变更，先修改本文档并通知全员，再改代码
